# ② 调研

## 目的

**带着 `01-needs/` 的诉求去调研**，不是漫无目的地收集资料。每做一步都问：这对我哪条诉求 / 哪个决策有影响？

## 方法约定

- 一手资料优先：官方 changelog、文档、自己实际上手 30 分钟的记录，高于转述文章
- 一产品 / 一主题一个文件，放 `competitors/`（或 `mechanisms/`）
- 所有结论汇总进 `findings.md`，每条结论必须带「→ 对决策的含义」
- 记下调研日期：AI 产品领域信息过期很快

## 竞品拆解模板

```markdown
# <产品名> 拆解（<日期>）
- 定位与目标用户：
- 我上手做了什么（30 分钟实录）：
- 核心流程记录 / 截图：
- 亮点（对哪条诉求成立）：
- 不借鉴的点（为什么）：
- → 对 PRD 的输入：
```

## 建议的调研对象

- 同形态：Raycast AI、Claude Desktop、Cursor、Warp、Open Interpreter
- 关键机制：上下文 / 记忆方案、工具调用与审批交互、多 agent 编排、权限模型

完成标志：`findings.md` 能直接回答「PRD 里每个关键决策，依据是哪条调研」。
