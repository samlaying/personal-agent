# product — 产品需求工程训练场

> 用「个人助理（PA）」这个真实场景练 AI 产品能力：把模糊的想法，完整走一遍
> **诉求 → 调研 → 过程 → PRD**。价值在过程材料的完整与真实，不在文档写得多漂亮。

## 流程与目录

| 阶段 | 目录 | 放什么 | 产出标准 |
|---|---|---|---|
| ① 诉求 | `01-needs/` | 真实使用里的痛点与想要的东西，如实记录、先不修饰 | 一份 `needs.md`，别人读完能复述我的场景 |
| ② 调研 | `02-research/` | 带着诉求去做的竞品拆解、机制调研，一对象一文件 | `findings.md` 里每条结论都能回答「这对决策意味着什么」 |
| ③ 过程 | `03-process/` | 发散的 brainstorm、被否掉的方案、关键取舍的决策记录 | `decisions/` 里每个重要取舍有背景、选项、代价 |
| ④ 产出 | `04-prd/` | 最终需求文档，版本化 | 自检清单全过：问题 / 方案 / 验收 / 取舍 四要素齐 |

依赖方向是单向的：后面阶段可以引用前面，前面不要预支后面的结论。

## 与工程文档的边界

- `docs/upgrade-plan.md` 是**工程侧**的现代化改造方案（怎么建）；本目录是**产品侧**的需求工程（建什么、为什么建）。
- PRD 定稿后，工程任务拆解仍走仓库现有方式（AGENTS.md 约定），不在本目录维护。

## 后续规划（本轮不做）

对抗性 Agent 评审：PRD 成稿后，用几个固定「挑刺」角色的 agent 攻击文档，攻击记录归档到 `03-process/reviews/`：

- **用户视角**：这个功能我真的会用吗？流程里哪一步会让我放弃？
- **工程视角**：哪些需求不可验收 / 成本失控？与 2MB / 80MB 硬指标冲突吗？
- **反方视角**：不做会怎样？哪些其实是伪需求？

评审后 PRD 出 v2，形成「成稿 → 攻击 → 修订」的训练闭环。
