# ④ PRD 最终需求文档

## 版本规则

- 文件名：`PRD-个人助理-v<N>.md`；改需求出新文件，不覆盖旧版
- v1 只承诺 MVP；v2 起的变更必须能追溯到某条 review 或 decision

## 自检清单（四要素，缺一不算完稿）

1. **问题**：解决谁的什么问题？链回 `01-needs/needs.md` 第几条
2. **方案**：核心体验与流程、MVP 边界（明确写出「本版不做」）
3. **验收**：每条需求可观察、可测试（不出现「好用」「智能」这类词）
4. **取舍**：关键取舍链回 `03-process/decisions/`；与硬指标（.app ≈ 2MB、空闲 RSS ≈ 80MB、零第三方依赖）不冲突

## 完稿后

交给对抗性 Agent 评审（见根 README「后续规划」）：评审 → 修订 → 出下一版。
